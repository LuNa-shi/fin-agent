## ArtifactRef Contract

Contract: `artifact-ref.v1`. Every reference requires `contract`, `artifactId`, `version`, `contentDigest`, `schemaVersion`, `producer`, `contractVersion`, `inputDigest`, `createdAt`, `asOf` and at least one location field: `path`, `uri`.

| Property | Runtime rule |
|---|---|
| `artifactId` + `version` | Stable logical identity; edits create a new positive version. |
| `path` / `uri` | At least one non-empty location is required. |
| `contentDigest` | SHA-256 of immutable object bytes. |
| `schemaVersion` + `producer` + `contractVersion` | Declares the producing schema and authority. |
| `inputDigest` | Canonical digest of the node input and upstream references. |
| `createdAt` + `asOf` | Exact creation and point-in-time timestamps. |

## Manifest and Run Lineage

Each durable authority root uses `artifact-manifest.v1` at `.artifacts/manifest.json`; immutable bytes live below `.artifacts/objects/sha256/`. Store scope is `cross-process-single-writer`.

- Run Analysis: `projects/<projectId>/.artifacts/manifest.json` under the Project authority root `projects/<projectId>/`.
- Idea Generation: `idea-generation/runs/<runId>/.artifacts/manifest.json` under the non-Project run authority root `idea-generation/runs/<runId>/`. Its manifest `projectId` stores the legacy contract compatibility identity `idea-universe:local-user`; it does not select or imply a physical Project path.
- Canonical Worldview: `canonical-worldview/workflow-runs/<runId>/.artifacts/manifest.json` under the globally serialized run authority root `canonical-worldview/workflow-runs/<runId>/`.

Manifest fields: `schemaVersion`, `projectId`, `storeScope`, `concurrencyNote`, `versions`, `successfulCommits`.

Version-entry fields: `ref`, `runId`, `nodeId`, `idempotencyKey`, `inputDigest`, `inputArtifactRefs`, `objectDigest`, `objectPath`, `committedAt`.

Successful-commit fields: `fingerprint`, `ref`.

Lineage projection fields: `runId`, `nodeId`, `idempotencyKey`, `inputArtifactRefs`, `ref`.

To reconstruct a run, select manifest version entries by `runId`, group them by `nodeId`, follow each entry’s `inputArtifactRefs`, and verify every terminal `ref` against its content-addressed object digest. RunStore node records persist the same formal refs for exact resume; Run Analysis additionally maintains its compatibility checkpoint `nodeExecutions` projection.

Durable mode: `explicit`; modes: `explicit`, `generated`. Only explicit caller keys are cached. Reusing the same explicit key and logical input returns the persisted successful result with zero backend/model calls.

Scope fields: `projectId`, `agentContractId`, `contractVersion`, `idempotencyKey`.

Logical-input fingerprint fields: `workflowId`, `nodeId`, `input`, `inputArtifactRefs`, `workspaceSnapshotId`, `priorReviewIssues`. Excluded automatic execution fields: `runId`, `asOf`.

Cacheable statuses: `succeeded`. Partial and failed results are never cached. Entries use `agent-result-idempotency/<scope-sha256-prefix>/<scope-sha256>.json`, content/result digests, and atomic completed-file publication.

## Atomicity and Deferred Boundary

- Artifact object bytes are content-addressed and immutable; a node batch becomes authoritative through one manifest publication. Canonical Worldview domain outputs become active only through the single completed run-publication marker described above.
- ArtifactStore scope is `cross-process-single-writer`; a cross-process single-writer lock serializes publication within each configured authority root without lost updates.
- Project WorkspaceService rejects traversal, absolute host paths, unauthorized mounts, and symlink escape. Idea-run execution additionally denies exact or nested Project mounts, Project tools, and Project write scopes. The durable typed event outbox remains the final WS-01 boundary.
- The Agent success cache atomically publishes immutable entries and coalesces concurrent identical requests inside one backend wrapper; distributed locking is not claimed.
